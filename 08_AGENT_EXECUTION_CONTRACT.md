# 08 — Autonomous execution contract

## Roles
Operate as lead research engineer, quant methodologist, forensic fundamental analyst, skeptical investment committee, interface engineer, and QA red team. Use independent subagents only when the runtime permits them and interfaces are coordinated.

## Priority rules
1. **Build Sprint 0–3 runnable vertical slice first.** Do not spend most time collecting glamour-stock anecdotes, building elaborate ML models or polishing charts.
2. A small honest, audited dataset is preferable to massive contaminated history.
3. Process failed examples as carefully as winners; denominators/base rates matter.
4. Keep core logic deterministic; LLM narrative must cite sources and distinguish inference.
5. If paid data is unavailable, finish adapter + demo fixture + honest limitation report; never secretly purchase or represent fixture results as live.
6. Actual command execution, tests and working files outrank proposals and roadmaps.
7. Keep end-to-end product runnable at each handoff.

## Suggested effort allocation
15% initial research/design; 30% data & cohort/feature engine; 20% backtest & validation; 15% API/dashboard; 15% testing and skeptical review; 5% packaging. Once P0 vertical slice passes, redistribute dynamically to gaps.

## Sprint log format
In `SPRINT_STATUS.md`: sprint, acceptance status, executed commands, outputs, test counts, observed failures, fixes, latest source timestamp, missing subscriptions, source lineage, next priority. In `NEXT_ACTION.md`: exact next command or file edit, known blocker, instructions to restart services and rerun tests. Create checkpoints/commits when the environment supports them.

## Gate rules
Don't proceed past a critical PIT leak, invalid future label isolation, nonreproducible backtest or unacknowledged fabricated input. Mark optional data-gated steps BLOCKED and continue on legitimate parallel work. Don't request ordinary design confirmations; choose sensible defaults. Seek permission only for irreversible actions, money, external publication, or required credentials.

## Final response from agent
1. Actual completed components and code locations.
2. Run instructions with commands verified on current environment.
3. Source coverage, data quality, provider/license limitations.
4. Backtest/sample periods and honest findings (including null results).
5. Number of deep-dive theses actually verified.
6. Explicit file links/paths, evidence, test outcomes.
7. PASS/FAIL/BLOCKED matrix and top risks.
8. Exactly one recommended next implementation step.

## Start now
Read this package, inspect repository and tools, create files, implement Sprint 0, and continue through Sprint 3 before optional sophistication. No standalone planning-only response.
